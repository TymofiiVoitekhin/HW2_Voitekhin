# HW2: Plan-and-Execute Agent з Agentic RAG та HITL

Цей репозиторій містить виконання Домашнього завдання №2. Було побудовано автономного агента з архітектурою Plan-and-Execute для доменної області IoT (інженерія електроніки). 

## 1. Архітектура та Реалізація моделі
На відміну від стандартного ReAct, де агент приймає рішення "на льоту", ця архітектура використовує три окремі вузли (LangGraph `StateGraph`):
1. **Planner (`planner_node`)**: Аналізує запит користувача та генерує список кроків за допомогою `with_structured_output`. Забезпечує стратегічне бачення.
2. **Executor (`executor_node`)**: Виконує один крок плану. Для кращого контролю за інструментами ми відмовилися від базового `ToolNode` і реалізували ручний виклик інструментів.
3. **Replanner (`replanner_node`)**: Оцінює прогрес і вирішує: продовжувати план, перепланувати чи завершити.

У якості LLM використано `ChatGoogleGenerativeAI` (Gemini 2.5 Flash, але змінювалась відповідно до лімітів). Використання моделей Pydantic забезпечило строгу типізацію виводу та нівелювало галюцинації форматів.

## 2. Agentic RAG (ChromaDB)
Реалізовано довідкову базу знань за допомогою локальної векторної бази `ChromaDB` (`PersistentClient`). База наповнена правилами конфігурації плат, інтерфейсів та специфікацій. Завдяки інструменту `search_knowledge` та чіткому docstring, агент самостійно приймає рішення: шукати інформацію в базі чи виконувати фізичну перевірку складу (`check_inventory`).

## 3. Persistence та Human-in-the-Loop (HITL)
- **Checkpointer**: Інтегровано `SqliteSaver`, який автоматично зберігає стан графа у файл `agent_state.db`. Продемонстровано успішне відновлення перерваної сесії (по `thread_id`).
- **HITL**: Інструменти `order_components` (замовлення) та `flash_firmware` (прошивка) є ризиковими. Граф зупиняється функцією `interrupt()`, зберігає стан і передає керування людині в термінал через `input()`. Агент продовжує роботу лише після команди `Command(resume=...)` зі статусом підтвердження чи відхилення.

## 4. З якими проблемами зіткнулися (Obstacles)
Під час розробки ми зіткнулися з кількома вузькими місцями:
1. **Rate Limits (429 RESOURCE_EXHAUSTED)**: Цикл Plan-and-Execute генерує багато швидких запитів, що вибивало ліміти API Gemini. Рішення: оптимізація промптів та перехід на легшу модель лінійки Flash.
2. **Галюцинації планування (Нескінченні цикли)**: При відхиленні дії (Reject) оператором, `Replanner` намагався вигадати нові кроки ("Зв'язатися з відділом закупівель"), для яких у нього не було інструментів, створюючи нескінченний цикл. Рішення: додавання суворих системних інструкцій у промпт `Replanner` для примусового завершення задачі (`finish`), якщо потрібні інструменти відсутні.
3. **Зсув індексів плану та вичерпання ліміту кроків (Агентна автономність)**: Архітектура Plan-and-Execute спирається на жорсткий лічильник виконання. Під час тестів Planner генерував план із 3 чітких кроків (1. Отримати умови з бази; 2. Оформити замовлення; 3. Прошити плату). Однак Executor проявив непередбачувану автономність і витратив один із кроків на додаткову перевірку — виклик check_inventory. Через це лічильник current_step досяг значення 3 раніше, ніж дійшла черга до фінального інструменту (flash_firmware). Replanner побачив, що виконано 3 з 3 запланованих кроків, і автоматично завершив роботу. Рішення/Висновок: Це не програмна помилка, а специфіка LLM-агентів. Для мінімізації таких зсувів необхідно вдосконалювати системні промпти (забороняти відхилятися від плану без вагомої причини) або додавати в Replanner логіку динамічного розширення ліміту кроків при виклику незапланованих інструментів.

## 5. Інструкція зі встановлення та запуску (PowerShell)

**Крок 1. Створення середовища та встановлення залежностей**
Відкрийте PowerShell у директорії проєкту та виконайте:
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Крок 2. Налаштування API ключа
Створіть файл .env у корені проєкту та додайте свій ключ:

GOOGLE_API_KEY="ваш_api_ключ_тут"

Крок 3. Запуск проєкту
Запустіть головний файл для демонстрації інтерактивного сценарію:

```
python plan_execute.py
```
